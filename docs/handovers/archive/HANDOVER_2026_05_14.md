### What went wrong today (read before restarting GPU work)

1. **WSL2 crashed once.** Root cause: I dispatched a subagent to do "cache build + training + eval" *and* I separately launched a chained `run_step4_pipeline.sh` for the same work. Both started training simultaneously → two TF processes contending for the RTX 3070 + 28 GB cgroup → WSL2 OOM cascade. Recovered; caches intact.
2. **Training restarted, killed mid-edge-suppress.** Second subagent reported "completed" while the bash + python it dispatched was still running edge-suppress. When the harness reaped the subagent's bash, the python died with it (no nohup; bash was the parent).

**Defensive rules going forward:**

- **NEVER run two GPU-bound processes concurrently.** Before any new GPU launch:
  ```
  nvidia-smi --query-compute-apps=pid,used_memory --format=csv
  pgrep -af "python.*train_diagnostic\|python.*eval_one_model\|python.*build"
  ```
  Both must be empty (or only contain processes you are about to chain into).
- **When dispatching a subagent for long training, the subagent must `nohup` or `setsid` the python so it survives subagent reap.** OR: launch the bash directly with `nohup ... &` from the main session and monitor via Monitor task, not via subagent.
- **WSL2 cgroup ceiling is 28 GB.** Set `tf.config.experimental.set_memory_growth(gpu, True)` (already done in `train_diagnostic.py` and `eval_one_model.py`). Do NOT use `ulimit -v` — CUDA reserves huge VA on init.

See `~/.claude/projects/-home-joshcullinan-RDP-CNN/memory/project_wsl_memory.md` for the full plumbing patterns.
